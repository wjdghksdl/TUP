# 🤝 TUP - 공모전 팀 매칭 서비스 플랫폼

> **사용자의 성향과 기술 스택을 분석하여 최적의 공모전 팀원을 매칭해주는 웹 서비스입니다.**
> 단순한 게시판 형태의 구인을 넘어, 세분화된 필터링과 매칭 요청 알고리즘을 통해 효율적인 팀 빌딩 경험을 제공합니다.

<br>

## 🛠 Tech Stack
* **Backend:** Python, Django, Django REST Framework (DRF)
* **Database:** MySQL
* **Frontend:** React, JavaScript, CSS
* **Infrastructure & DevOps:** Docker, Docker Compose

<br>

## 📁 Repository Structure (Monorepo)
프론트엔드와 백엔드가 분리된 모노레포(Monorepo) 구조로 구성되어 있으며, `docker-compose`를 통해 전체 환경을 한 번에 실행할 수 있도록 설계했습니다.
* `/backend`: Django 기반의 RESTful API 서버 및 데이터베이스 모델링
* `/frontend`: React 기반의 SPA(Single Page Application) 사용자 인터페이스
* `docker-compose.yml`: 컨테이너 환경 통합 배포 설정 파일

<br>

## ⚙️ 핵심 구현 기능 (Backend & Architecture)

### 1. 팀 빌딩 및 매칭 RESTful API 설계
* 사용자의 기본 정보, 보유 기술 스택, 희망 직무(포지션) 데이터를 등록하고 조회하는 API를 구축했습니다.
* 공모전 모집 게시글 CRUD 기능과 더불어, 특정 조건(개발 스택, 성향 등)에 맞는 팀원을 검색하고 필터링하는 기능을 RESTful API 규격에 맞게 구현했습니다.
* 매칭 요청, 수락, 거절에 따른 상태 변화를 클라이언트(React)와 JSON 형태로 원활하게 통신할 수 있도록 서버 응답을 최적화했습니다.

### 2. 관계형 데이터베이스(RDB) 설계 및 모델링
* 유저(User), 팀(Team), 공모전(Contest), 매칭 요청(Match Request) 간의 복잡한 비즈니스 로직을 RDB 구조로 도출했습니다.
* 다대다(N:M) 관계(예: 유저와 기술 스택, 팀과 지원자)를 풀기 위해 중간 매핑 테이블을 설계하여 데이터 정합성을 확보했습니다.

### 3. Docker 기반 독립적 개발/배포 환경 구축
* `Dockerfile` 및 `docker-compose.yml`을 작성하여 프론트엔드(React), 백엔드(Django), 데이터베이스(MySQL)를 각각의 독립된 컨테이너로 분리했습니다.
* 운영체제(OS) 환경에 구애받지 않고 명령어 한 줄(`docker-compose up`)로 동일한 테스트 및 서비스 배포 환경을 세팅할 수 있도록 인프라를 구성했습니다.

<br>

## 🚀 기술적 고민 및 트러블슈팅 (Future Work)

### 1. N+1 문제 해결 및 쿼리 최적화 도입 필요성
* **상황:** 유저 목록과 각 유저가 가진 기술 스택(N:M 관계)을 한 번에 조회하는 매칭 목록 API에서 쿼리가 비정상적으로 많이 발생하는 **N+1 문제**의 가능성을 확인했습니다.
* **개선 계획:** 현재 데모 규모에서는 작동에 무리가 없으나, 데이터가 확장될 경우 심각한 데이터베이스 병목이 예상됩니다. 추후 Django ORM의 `select_related`(정방향 참조)와 `prefetch_related`(역방향 참조)를 적극 적용하여 데이터베이스 I/O 횟수를 획기적으로 줄일 예정입니다.

### 2. 매칭 알고리즘 고도화 설계
* **상황:** 초기 기획에서는 사용자의 활동 내역을 기반으로 한 협업 필터링 수준의 추천 알고리즘을 도입하고자 했으나, 프로젝트 마감 기한으로 인해 스택 일치도를 기반으로 한 단순 필터링 조회 매칭으로 축소 구현했습니다.
* **개선 계획:** 향후 실사용 데이터가 누적되면, 사용자 성향 벡터를 계산하여 가장 잘 맞는 팀원을 상단에 띄워주는 고도화된 추천 시스템 아키텍처로 백엔드 로직을 확장할 계획입니다.
